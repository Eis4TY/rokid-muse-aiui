# 常见问题

先在 skill 文件夹运行：

```sh
python3 scripts/setup.py check
python3 scripts/setup.py status
```

| 现象 | 操作 |
| --- | --- |
| 未找到眼镜 | 换数据线；开启 USB 调试；眼镜上允许电脑调试 |
| unauthorized | 在眼镜确认 USB 授权后重试 |
| 多台设备 | 拔掉其他设备，或命令末尾加 `--serial 实际序列号` |
| 双击提示 command 无权限 | 终端执行 `chmod +x 开始配对.command`；也可用 `python3 scripts/setup.py setup` |
| 缺少 adb/aix | 按快速上手安装；已安装则确认 PATH；重开终端 |
| APK 签名不一致 | 停止安装；使用原签名包升级。不要直接卸载，卸载会丢失原生身份与未交接授权 |
| Muse 搜不到广播 | 手机系统“设置 → 蓝牙”中忽略眼镜原有连接（仅断开不够），保持 USB；运行 `pair` 并重新扫描 |
| 广播器/GATT server 不可用 | 确认蓝牙已开启；此型号可能不支持外设模式，需要实机验证，不能以安装成功代替兼容性验证 |
| 配对窗口已关闭 | `python3 scripts/setup.py pair`，重新打开 10 分钟窗口 |
| Rokid App 无法回连眼镜 | 先关闭手机 VPN，再通过 Rokid App 回连；确认成功后，非美国地区使用 Muse AIUI 时再开启 VPN |
| 本机交接 HTTP 403 / 尚未绑定 | `python3 scripts/setup.py setup --rebind` 修复绑定，再 `open`；不会删除已有 Muse 授权 |
| 绑定 45 秒未确认 | 确认眼镜 AIUI 可启动，重新运行 `setup --rebind`；不要在初始应用绑定完成前拔 USB |
| 本机 18790 端口占用 | 关闭其他安装/绑定脚本再运行；脚本在占用时不会覆盖绑定 |
| 手机授权已收到，但 AIUI 验证失败 | 先关闭手机 VPN，用 Rokid App 回连眼镜；连接成功后，非美国地区开启并保持手机 VPN，再 `open` 或刷新；保持组件运行，不要立刻重配 |
| 新设备授权验证 HTTP 401 | 授权无效；确认手机配对使用当前账号，重新 `pair` → 手机确认 → `open`。网页登录成功不等于设备授权成功 |
| HTTP 403 / 网络失败 | 检查手机/眼镜网络后重试；仍失败记录状态码和阶段，不能仅凭码断言账号被禁用 |
| delivered=true，AIUI 却未授权 | 确认应用定义的稳定 agentId 与之前一致；换 ID 会进入另一套存储。不要反复重配掩盖 ID 错误 |
| 更新后仍提示六位交接码 / Version match … skipping extraction | 旧代码缓存可能仍在运行。使用 最新完整包的 setup 脚本升级：稳定 agentId + 新内部 VERSION；确认 loaded 日志 release=0.3.1 |
| delivered=false，令牌缺失 | 授权交接尚未完成，不能直接认定配对失败。检查 handoff_ready，再看新版页面“本机授权交接”或“Muse 云端授权验证”的具体错误 |
| 眼镜 Android 没有默认 IP 路由 | 不等同于 AIUI 无网络，AIUI 可能通过手机通道请求；应验证实际 AIUI HTTPS 请求，而不是只查 Android 路由 |
| 已配对但会话未接入 | 授权交接与 WebSocket 会话是不同阶段。检查手机网络与 Rokid 连接；非美国地区使用时保持手机 VPN 开启，电脑的 VPN 不会自动为眼镜提供网络 |
| 蓝牙名暂时变成 MuseGadget | 正常广播建立后会恢复原名；异常退出时重新打开组件恢复，不要固定改成别人眼镜的名称 |

`status` 的 `handoff_ready=false, delivered=true` 是正常已交接状态；原生组件已删除其令牌副本，AIUI 保留自己的授权。`status` 不返回任何令牌内容。

升级保留数据；`--rebind` 更换本机应用绑定密钥，不撤销账号设备授权。清空数据、卸载、恢复出厂会改变身份或丢失授权，需要明确知道后果后操作。本 skill 不自动执行这些操作。

## Muse 搜不到：先确认眼镜确实在广播

先运行 `python3 scripts/setup.py pair`。0.3.1 安装助手会核对当前配对进程的 `ADVERTISING_LOCAL_PROTOCOL` 日志，明确确认成功后才提示手机扫描。`native_pairing=true` 只是组件能力标识，`binding_ready=true` 只是本机绑定；二者都不是广播成功证据。

若眼镜显示“名称准备失败”，先升级至 0.3.1 完整包（已包含原生竞态修复），再 pair。旧版 Activity 与 Service 重复初始化时会提前恢复临时名称，导致广播失败。不要只反复扫描手机、改 VPN、重新授权或清空组件。

| 眼镜实际结果 | 下一步 |
| --- | --- |
| 名称准备失败 / 广播初始化超时 | 使用新版原生 APK，保留数据增量升级；仍失败收集下面的原生阶段日志 |
| 广播失败：数字 / GATT 失败：数字 | 记录完整错误码，确认蓝牙开启、权限已授予；不要直接判定手机问题 |
| 广播成功后手机仍搜不到 | 手机系统忽略原蓝牙连接，退出 Muse Add Device 再进入，保持距离近；窗口关闭则 pair |
| 手机已确认配对、handoff_ready=true | 不再反复 pair；关闭手机 VPN → Rokid 回连 → 开启 VPN → open 验证授权 |

以下命令只打印原生阶段日志，不读取授权存储；不要回传完整 logcat 或蓝牙 dumpsys：

```sh
adb logcat -d -v epoch -s MusePair:I '*:S' -t 2000
```

Windows 命令行请将 `'*:S'` 改成 `"*:S"`。回传命令结果与眼镜错误文字；可遮盖自己的蓝牙名称。发送前检查无账号/令牌内容。
